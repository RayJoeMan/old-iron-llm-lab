## Disagreements adjudicated

1. **probe_c2 double-counting (Astra #5 vs Opus "do not double-count").** Opus is right on the code as written: a late row is always alone in its (task, attempt) group — attempt numbers increment atomically per claim, so no second row can share a late row's attempt, and the two sums are disjoint. No fix for double-counting; the separate M5 defect (issue #23) in the same counter was real and is fixed on its own terms.
2. **Verdict fencing severity (Astra HIGH vs Opus LOW).** Both describe the same hole. Severity for *this A/B*: LOW — exactly one checker process runs, and the gate's sim checkers verdict immediately after claiming. Severity for a production bus: HIGH — it is the first hardening item in any adoption path. Recorded as disclosed with that split.
3. **Validators (Astra MEDIUM vs Opus clean).** Compatible, not contradictory: symmetric across arms (so the comparison is fair) and permissive in absolute terms (so the metric's name must stay honest). Issue #21.
4. **"First attempt" semantics (both flagged, differently framed).** The metric measures the first *validated* (C2) / first *surviving delivered* (B) artifact, not claim attempt 1 — a killed first attempt that never produced an artifact leaves nothing to score. The metric keeps its v1 name for comparability and gains a filed definition (amendment A-3) rather than a rename, so v1↔v2 tables stay readable.

## Design amendments (filed here, before runs; design text unchanged)

- **A-1 (leak metric):** §4.2's per-attempt leak accounting applies to Arm C2. Arm B's byte-unmodified harness carries no task/attempt tags and has no verdicts; B reports `budget_burned_calls` (calls burning ≥95% of budget) as context. The two numbers are never compared as the same metric.
- **A-2 (lease semantics):** §3.1's "a lease expiry consumes the attempt" is reaper-mediated, as in v1: an expired-but-unreaped claim can still post on-time. The attempt is consumed when the reaper acts.
- **A-3 (definitions):** "First-attempt pass" = first validated/delivered artifact (see disagreement 4). The §7 kill trigger counts lifecycle completions (done + deadletter for C2).
- **A-4 (pointer):** §9 leg 5's "§4.4" should read §4.3 (the contention protocol lives there; there is no §4.4).
- **A-5 (known limitations, with bias directions):** B's delivery fencing and same-worker overwrite undercount B's duplication (bias: pro-B) · verdict fencing is single-checker-safe only (bias: none at this configuration) · transport errors consume C2 attempts but not B's (bias: anti-C2 under infrastructure failure) · settle-window completions can land after the wall endpoint (bias: negligible, both arms) · shipped-wrong is validator-relative (bias: symmetric).
